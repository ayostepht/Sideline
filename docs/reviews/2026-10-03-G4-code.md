### Minor

- **[m1] FIXED (orchestrator, before this report was saved).** `scripts/gate/soak.ts`'s module doc overclaimed a security property: it implied secrets never show up in `docker inspect`. `--env-file` only avoids the value appearing in the command line/`ps`; it does not keep the resolved env out of the container's own stored config, which `docker inspect` exposes by design — inherent to how Docker injects env vars at all, not a new hole introduced by this script, and no code path in this diff actually prints that output anywhere. The module doc now states this narrower, accurate claim and warns against pasting raw `docker inspect` output for this container while it's running.
- **[m2]** `tests/golden/priority-advisor.golden.test.ts` (6 insertions/8 deletions) is inside qa-engineer's owned path (`tests/`) but was edited as part of `624771b`'s `fix(core)` commit (T4.9, analytics-engineer-flavored). The change itself is correct (updates a hardcoded `-4` EDT offset expectation to the real January EST value the new DST-aware code now computes) and the diff size (14 total changed lines) is within CLAUDE.md section 1's 15-line orchestrator integration-fix allowance, and the commit message explicitly flags the cross-boundary edit ("owned by qa-engineer") rather than silently doing it — so this reads as a correctly-handled exception, not a violation. Flagging only so the gate report records that this was noticed and judged acceptable, in case the pattern recurs at larger size in a future phase.
- **[m3]** `apps/web/lib/server/waivers.test.ts:402-417`'s only end-to-end `nextClearAt` assertion for T4.9's fix uses a January (EST) date, so it doesn't actually exercise the DST branch at the web-integration layer — the EDT regression itself is only covered by `packages/core`'s unit tests and the golden test. Low risk since the DST math lives entirely in `packages/core` and is thoroughly unit-tested there (new "DST regression" and "DST changeover" tests in `priority-advisor.test.ts`), but a future regression in how `waivers.ts` wires the call (e.g. accidentally reintroducing a hardcoded offset argument) wouldn't be caught end-to-end until an EDT month. Not blocking; logged to `docs/PROGRESS.md` backlog for qa-engineer.
