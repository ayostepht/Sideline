# UX review: Phase 5 Batch D (T5.5a, T5.5b, T5.5c)

Date: 2026-10-03
Scope: Home (`/l/{id}`), League (`/l/{id}/league`), Matchup (`/l/{id}/matchup`) at 390/768/1280px, light and dark. 18 fresh captures plus a real `pnpm test:a11y` run across all three Playwright projects.

## Verdict

CHANGES REQUIRED (one Blocker, one Major; both fixed same-session). See `docs/PROGRESS.md` backlog for the Minor/nit findings carried forward.

## Findings

| Severity | Location | Finding | Status |
|---|---|---|---|
| Blocker (B1) | `apps/web/components/positional-strength-grid.tsx` | Heatmap's `.overflow-x-auto` wrapper is a real axe **serious** violation (`scrollable-region-focusable`), confirmed failing on `mobile-iphone`/`mobile-pixel`, light and dark (4/39 `pnpm test:a11y` checks). At 390px only QB/RB/WR are visible with zero scroll affordance and no keyboard access to the rest. | Fixed, see fix-round report below. |
| Major (M1) | `apps/web/app/l/[leagueId]/matchup/_components/score-range.tsx` | Score-range chart's line strokes use background-fill tokens (`text-muted`/`text-accent-soft`) as foreground strokes: measured contrast 1.07-1.51:1 against the card background (needs 3:1), nearly invisible in light mode. Defeats the chart's purpose -- the "range" is the whole point. | Fixed, see fix-round report below. |
| Minor (m1) | `apps/web/app/l/[leagueId]/league/_components/manager-tendencies.tsx` | No pluralization: "1 transactions", "1 waiver claims won" instead of singular forms. | Backlog (`docs/PROGRESS.md`, Phase 5 section). |
| Minor (m2) | `power-rankings.tsx`, `all-play-luck.tsx`, `manager-tendencies.tsx`, `playoff-odds.tsx` | All four new League sections stay single-column-stacked-card at every breakpoint including 1280px, while Standings on the same page gets a proper desktop table -- leaves unused horizontal space, contradicts PLAN 6.1's "desktop gets more density" principle. | Backlog, same section. |
| Minor (m3) | Home card + Matchup page | Win probability shown three times in quick succession (banner sentence, "YOU 55%" card, "TIE 0%" card) with no added information -- ~300px of mobile scroll before Score Range is reached. | Backlog, same section. |

Likely intentionally out of this batch's scope (not in ADR-016 amendment 3's T5.5a brief) -- confirmed not a missed requirement, just noting for a future phase if Steph wants it. | Informational, not backlog-tracked (out of scope by design). |

## What works well

- Win-probability framing ("You have a 55% chance to win against Team 03") is plain, friendly, leads with the number -- matches PLAN 6.1's "insight first" principle exactly.
- All three new areas reuse existing, previously-reviewed primitives (ReasonChips/WhySheet, PositionBadge, the `accent-soft` "this is you" row-highlight convention, the stale-data banner) rather than inventing one-offs -- nothing reads as a different app.
- Playoff-odds-unavailable and non-FAAB-league copy is warm and explains why, exactly as asked.
- Heatmap's actual cell coloring (background fills behind bold text, numeric delta plus direction icon on every cell) is legible in both themes and never relies on color alone -- only its reachability at mobile width was the problem (B1), not the color coding itself.

## Checks run by the reviewer

- 18 fresh screenshots via `pnpm screens` against a seeded temp DATA_DIR (never `./data`)
- Real `pnpm test:a11y` run (`e2e/routes.spec.ts`) across desktop-chromium/mobile-iphone/mobile-pixel, light and dark, for all three routes: 35 passed, 4 failed (all B1)
- Pixel-sampled contrast measurement of the score-range chart's rendered colors against the card background in both themes (M1)
