# UX review: Phase 3 Batch H (Home, My Team, Lineup)

Date: 2026-10-03. Branch: `phase/3-scoring`. Routes: `/l/{id}`, `/l/{id}/team`, `/l/{id}/lineup` (+ `?mode=safe`, `?mode=upside`, `?roster=2`), 390/768/1280px, light/dark.

VERDICT: CHANGES REQUIRED. Two Major findings have fixes dispatched (in flight as of this write): M1 (frontend), M2 (backend). M3 and M4 also dispatched/queued.

## Findings

- **[M1] Major**: ADR-011's "one lime accent per page" is styled two different ways for the same signal: Home's recommendation card uses vivid `bg-primary` fill, Lineup's summary banner uses the muted `bg-accent-soft` tint despite its own comment claiming to be "the" accent. Fix in flight: unify Lineup's banner to match Home's vivid treatment (frontend-engineer, scope: `lineup/_components/summary-banner.tsx`).
- **[M2] Major**: Safe and Upside modes render numerically identical to Projected for every player right now. Root cause: the same-day `readPositionCv` fix (commit `352af52`) requires 4 of a player's own weeks before they count toward the position CV prior; at week 4 of the season (today's real week), nobody qualifies yet, so the prior is empty, `sd` collapses to 0, and floor = ceiling = proj everywhere. This is live and would surface at the G3 human checkpoint on Steph's real league. Fix in flight: backend-engineer lowering/restructuring the per-player minimum so early-season leagues still get a usable (non-degenerate) prior, with a new regression test proving real floor/ceiling separation in a week-4-shaped scenario.
- **[M3] Major**: swap-list player names truncate ambiguously at 390px (two different rows can look identical, e.g. "Ladd McConk..." vs "Ladd McCon..."), with only an inert `title` attribute for disambiguation on touch devices. Fix in flight: frontend-engineer, `lineup/_components/swap-list.tsx`, wrap or widen rather than truncate.
- **[M4] Major**: `e2e/pages.spec.ts` STATE-3 still expects the old Lineup stub page; fails on all 3 Playwright projects now that T3.8a replaced the stub. Same finding as the code review's M1. Not fixed directly; folded into T3.9's brief (qa-engineer owns `e2e/`).
- **[m1] Minor**: the vivid lime fill used for the "one accent" content callout is also reused for persistent nav/toggle "selected" chrome (sidebar active row, bottom-tab active icon, Lineup mode-toggle active pill), so a strict per-pixel reading of "lime once per page" isn't met once navigation chrome counts. **Orchestrator decision: not a bug.** Chrome (persistent selection state) and content (one-time recommendation callout) are different visual roles even when they share a color; ADR-011's intent is "don't wash lime across unrelated content items," not a literal single-use rule across all UI layers. No fix needed; logged as a ratified clarification, not a backlog item.
- **[m2] Minor, out of batch scope**: a flaky axe `color-contrast` finding on `/settings` dark theme (`button[data-state="on"] > span`), reproduced 2 of 5 runs. Settings wasn't touched by this batch. Logged to backlog, not evaluated further.
- **[n1] Nit**: the bottom tab bar appears to duplicate mid-page in full-page screenshots on long pages (Team, Lineup). Confirmed a Playwright `fullPage: true` capture artifact with `position: fixed` elements, not a real bug — it stays correctly pinned during actual scrolling. No action.

## What works well

`MatchupGrade`/lock/injury badges consistently pair icon + text (never color alone); the neon-purple `variant="you"` badge renders correctly in both themes; `ScoreboardHero` reads as a coherent, genuinely shared "scoreboard feel" component between Home and My Team; the Lineup page's responsive stacking (390px stacked, 768px+ side by side) and 44px touch targets are all correct.

## A11y

`pnpm test:a11y` (axe, all 3 Playwright projects, both themes): 0 serious/critical violations on the three in-scope routes. Only failures are M4 (STATE-3, 3/3 projects, expected and tracked) and the out-of-scope m2 flake.
