## Findings

No Blocker or Major findings. All 5 "Phase 4 live fixes" render correctly in a real build, not just in source.

- **[m1] Minor (confirmed non-issue).** A known, previously-documented full-page-screenshot capture artifact (the fixed bottom nav bar appears duplicated mid-page at 390/768px) is still present. Re-verified the content underneath renders correctly and completely; this is a capture tool quirk (`scripts/screens.ts` full-page screenshot vs. a `position: fixed` nav), not a real rendering bug. Same root cause already logged as n1 in `docs/reviews/2026-10-03-p4-batchF-ux.md`. No action needed.
- **[m2] Minor.** The WhySheet's own internal max-height/scroll means a full-page screenshot with the sheet open only captures the first ~2 reasons before the sheet's scroll boundary clips it. Not a bug (the sheet scrolls fine interactively; the static non-sheet `WhyBody` preview rendered all 6 reasons correctly), just a screenshot-tooling limitation.
- **[n1] Nit, already deferred by Steph at G3/backlog, reconfirmed unchanged:** Lineup's summary banner can say "+0.0 pts" while the swap list below shows a net-negative sum; Home/My Team use `variant="accent"` for "Your team" where League/Standings use the purple "You" badge for the same concept. Not re-flagged as new, left as already-triaged backlog.

## Live-fix verification (explicit)

1. **ReasonChip wrapping (`28a19f1`).** Confirmed on `/dev/gallery` at 390px light/dark with a deliberately worst-case long label: wraps cleanly across 3 lines, no truncation, no horizontal overflow, value/impact stay right-aligned and legible. Also confirmed on real Players detail data (Jahmyr Gibbs, Patrick Mahomes) where real backend reason text wraps correctly inline at 390px.
2. **Lineup's Optimal column with inline chips removed (`10cd72e`).** Confirmed at all 3 breakpoints, both themes. Each Optimal row is PlayerRow + a single "Why?" trigger — clean, dense spacing, no empty gap, no orphaned whitespace. Current column correctly shows no "Why?" trigger at all (`showReasons={false}` in `lineup/page.tsx`).
3. **Rounded reason values (`10cd72e`).** Confirmed via `/dev/gallery`: a raw float-style input renders as "12.5" / "-0.4 pts" (one decimal, no long tail); string values pass through unchanged. Confirmed again on real Players detail data — one decimal throughout, zero raw floats found anywhere in the 7 routes reviewed.
4. **Waivers auto-drop feasibility fix.** Not a visual change, out of scope; confirmed no empty-slot regressions visible in the Waivers table at any width.
5. **Dev-workflow-only fix (SIDELINE_DEV_ORIGINS).** Not applicable to a visual review.

## ADR-011 compliance

Palette, lime-as-fill, Inter, 4px corners and scoreboard density all hold across all 7 routes in both themes. Exactly one vivid lime content accent per page confirmed (Home/My Team's "Your lineup is optimal" CTA, Lineup's "N swaps available" banner, Waivers' "Top waiver target" banner; sidebar-nav selection is the documented persistent-chrome exception, ADR-013 item 23, not a violation). No stray hex values; position badges and the purple "You" badge are pixel-identical across all routes.

## A11y results

`pnpm test:a11y` (full run, all 3 Playwright projects x the complete route list):

- UI2 (axe, zero serious/critical): 0 failures across every route, both themes, all 3 projects.
- UI5 (no horizontal scroll at 390px): 0 failures across every route.
- 330 passed, 3 failed, 14 "did not run."
- **The 3 failures are the same pre-existing test**, `e2e/pages.spec.ts` "STATE-3: each placeholder page links to Home and My Team," on all 3 main projects — unrelated to axe/UI2/UI5 or the Phase 4 live fixes. Root cause: the test still looks for `data-testid="stub-page"` on `/waivers` and `/players`, but those stopped being stubs this phase (T4.6a/T4.6b shipped real pages). A qa-engineer test-maintenance gap, not a UX/a11y defect.
- The 14 "did not run" are the dependent `*-notfound` projects, cascaded-skipped because their declared dependencies (the 3 main projects) reported a failure — not a separate issue.
- Two pre-existing, unrelated environment blockers (a dead `.next/dev/lock` file, an orphaned `next-server` process on port 3101) were cleared before the run; no source files touched.

## What works well

- The two most data-dense surfaces this phase touched (Lineup's Optimal column, Players detail) read noticeably calmer after the live fixes.
- `reason-format.ts` (`formatImpact`/`formatProjectedPoints`/`formatReasonValue`) is a strong single source of truth — every numeric reason across Lineup, Waivers and Players detail reads with identical one-decimal, signed, tabular-nums formatting.
- Position badges, the purple "You" indicator, the amber stale banner, and the lime recommendation banner are pixel-identical wherever they recur.
- Mobile card / desktop table transitions hold up cleanly at the 768px midpoint too, not just the two archived breakpoints.
