# UX review: Phase 6 Batch A (T6.1, T6.2, T6.3a)

Date: 2026-10-04
Scope: Home, Matchup, League at 390/768/1280px, light and dark (18 screenshots) -- first PWA manifest/icons and theme-color fix in this codebase, plus a regression check against the new auth gate (T6.1) and no-auth-by-default behavior.

## Verdict

APPROVE. Zero Blocker/Major findings.

## Findings

| Severity | Location | Finding | Status |
|---|---|---|---|
| Minor (m1) | `apps/web/public/icons/icon-512.png`, `icon-192.png` | The purple accent bar's bottom corners sit just outside the standard 80%-diameter maskable safe-zone circle -- a few px of clipping under an aggressive circular OS mask (some Android launchers). Barely visible (only the bar's sharp corners, not the main chevron glyph). | Backlog (`docs/PROGRESS.md`, Phase 6 section). |
| Nit (n1) | `apps/web/app/layout.tsx` | Static pre-hydration `theme-color` always starts at the dark value; a system-light user sees dark browser chrome for one tick before `ThemeColorSync` corrects it on mount. Already deliberately documented/reasoned about in the code comment (no SSR theme cookie exists to do better). | No fix requested. |
| Nit (n2) | `apps/web/app/favicon.ico` | The 16x16 embedded frame is a bit soft/anti-aliased (downscaled from 48x48 rather than hand-tuned). Still legible as a shape in a browser tab. | Backlog, lowest priority. |

## A11y results

`pnpm test:a11y` (350 tests, all 3 Playwright projects): **350 passed, 0 failed**. Every route including Home/Matchup/League (base and team-detail) passed UI2 (axe) and UI5 (no 390px h-scroll), both themes.

## Verified explicitly

1. Zero visual regression across all 18 screenshots -- no broken head tags, no layout shift, consistent ADR-011 treatment.
2. Theme-color correctness verified with real live JS execution (the CSP issue a parallel task had hit earlier is confirmed fixed): `meta[name="theme-color"]` correctly tracks the resolved theme through a live toggle, matching `getComputedStyle(document.body).backgroundColor` at each step.
3. `/manifest.webmanifest` is valid, served with the correct content-type, real icon entries including a `maskable` variant, `theme_color`/`background_color` both a real ADR-011 palette color.
4. Icons are on-brand, crisp, not corrupt (except the two findings above).
5. No auth-wall surprise: confirmed on both a fixture-seeded server and the live `dev:lan` server that with no `APP_PASSWORD` set, every route and PWA asset returns 200 directly, no redirect to `/login`.

## What works well

- `ThemeColorSync` is a clean, well-reasoned pattern worth reusing for any future "needs the real resolved theme, not just the OS query" problem.
- `proxy.ts`'s `PUBLIC_PATHS` allowlist correctly keeps PWA installability assets reachable pre-login while gating real content -- good instinct for not breaking "Add to Home Screen" behind the auth wall.
- League and Matchup hold up well at every width: the desktop League table is dense and scannable, mobile's card re-flow keeps semantic color consistently paired with text/icon everywhere.
