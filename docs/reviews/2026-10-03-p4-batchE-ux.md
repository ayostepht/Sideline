# Phase 4 Batch E UX review

Date: 2026-10-03. Branch: `phase/4-waivers`. Routes: `/l/{leagueId}/{waivers,players,players/{playerId},lineup}` at 390/768/1280px, light/dark. Reviewer: ux-reviewer subagent.

VERDICT: CHANGES REQUIRED (1 Blocker, 1 Major; fixed before Batch F)

## Findings

**[B1] Blocker** `/lineup` at 390px, both themes, every mode/roster — real horizontal scroll (`scrollWidth` 479-480px vs. 390px `clientWidth`), confirmed by the project's own `pnpm test:a11y` UI5 spec failing on all three Playwright projects. Root cause: `apps/web/app/l/[leagueId]/lineup/page.tsx:134`'s `className="grid gap-3 md:grid-cols-2"` has no explicit `grid-cols-1`, so the single implicit column at mobile widths sizes to its widest descendant's content instead of 100% of the viewport — meaning `ReasonChip`'s `max-w-full`/`truncate` never had a definite ancestor width to clamp against. T4.8c's new "X.X proj pts" text is what finally pushed a chip wide enough to trigger it (measured full chip text 444px wide before the page's own padding). At 768px/1280px, where `md:grid-cols-2` gives a real `1fr` track, the same chip truncates correctly — the bug is layout, not the chip. **Fix:** `grid grid-cols-1 gap-3 md:grid-cols-2` on `page.tsx:134`.

**[M1] Major** `/waivers`, all widths, both themes — the glossary `<details>/<summary>` disclosure (added specifically to avoid a sub-44px hover-only tooltip target) still ships a ~16px-tall clickable area: `waiver-board.tsx` puts padding on `<details>`, none on `<summary>`. Measured and click-tested: clicking inside the visually-obvious card padding does not open it. **Fix:** move the height/padding onto `<summary>` directly (`min-h-11` matching the file's existing `ToggleGroupItem`/`Button` convention).

## Minor / Nit (backlog, not blocking)

- **[m1]** Waivers' "Suggested drop" shows the identical player for all 75 candidates on both tabs (correct behavior — always the lowest ROS-value bench player, independent of position) with no inline cue that this is intentional; only explained one click deep in the "Why?" sheet. Suggest an inline qualifier like "Suggested drop (lowest value overall): ...".
- **[n1]** Fullback-position players render with a generic "FLEX" badge (pre-existing `PositionBadge`/`normalizePosition` fallback, not introduced by this batch — now visible because Players surfaces the full pool). Low priority.

## What works well

- Touch targets are a consistently enforced 44px system everywhere except the M1 exception.
- Waivers' position-filter refetch gives real, non-disruptive feedback (spinner + "Updating" `role="status"`, dimmed list with `aria-busy`); tab switching is instant with zero refetch.
- `Sparkline` ships an `sr-only` data-table fallback and honestly labels its line "Season average."
- Color contrast measured directly: `muted-foreground` (the new "proj pts" text) 6.2:1-10.2:1, `primary`/`primary-foreground` 12.2:1 — comfortably AA/AAA.

## Accessibility (axe + no-hscroll, `pnpm test:a11y`)

Zero axe violations (serious/critical) on all four routes, both themes, all three Playwright projects (18/18). UI5 (no horizontal scroll @ 390px): Waivers and Players pass on all three projects; Lineup fails on all three (B1 above).
