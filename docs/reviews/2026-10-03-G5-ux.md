# UX review: G5 gate, final Phase 5 screens

Date: 2026-10-03
Scope: Home, Matchup, League at 390/768/1280px, light and dark (18 screens), plus Waivers/Lineup/League-team-detail spot-checks for regression. First run of the canonical `pnpm test:a11y` suite with port 3000 free.

## Verdict

APPROVE. Zero Blocker/Major findings.

## Findings

| Severity | Location | Finding | Status |
|---|---|---|---|
| Minor (m1) | League, all 6 sections except Standings | Only Standings marks the viewer's own team ("You" badge + row tint) -- Power Rankings, All-Play/Luck, Positional Strength, Manager Tendencies, and Playoff Odds all show the viewer's row as a plain, unmarked entry identical to every other team. Breaks the "You" convention used everywhere else in the app (Standings, Home, Matchup's swing players). | Backlog (`docs/PROGRESS.md`, Phase 5 section). |
| Minor (m2) | Matchup, 1280px | Swing Players list stays a single ~670px stacked card list at desktop width, leaving ~40% of the content column empty -- same class of issue already logged for League's 4 non-tabular sections, now confirmed to extend to Matchup too. | Backlog, same section. |
| Nit (n1) | League team detail (not a Phase 5 screen) | One `pnpm screens` run returned a transient HTTP 500 on this unrelated, pre-existing route; two immediate reruns both returned 200 with correct content. Not reproduced enough to diagnose, not in Phase 5's scope. Logged as a reliability data point only. | Not backlog-tracked (couldn't reproduce); noted for qa-engineer/devops-engineer awareness if it recurs. |

## Re-confirmed, not re-flagged (already-fixed Batch D issues, holding in the final build)

- Positional heatmap (previously Blocker): card list at 390/768px, all 7 positions visible, zero scrolling, zero keyboard-trap risk. Proper table at 1280px. Both themes clean.
- Score-range chart line contrast (previously Major): clearly visible bars in both themes, all widths.
- Score-range "your" dot contrast (open backlog item): re-measured, same severity as logged (core ~3.2:1, edges ~1.18:1 against white) -- not worse in the final build.
- Manager Tendencies pluralization, Home/Matchup's triple win-probability display, `sparkline.tsx` latent overflow risk: all confirmed present, unchanged severity, correctly left in backlog.

## A11y results (canonical suite, first run with port 3000 free)

`pnpm test:a11y`: **350 passed, 0 failed, 0 skipped** across desktop-chromium, mobile-iphone, mobile-pixel (plus not-found sub-projects), every route, both themes. Matchup and League's UI2 (axe) and UI5 (no-h-scroll) cases all pass on every project. This is the first canonical-suite confirmation of the heatmap accessibility fix (the mid-batch fix round used an equivalent ad hoc axe scan since port 3000 was occupied at the time) -- zero new violations found.

## What works well

- The heatmap fix holds up completely under real conditions: identical, fully-reachable data at every breakpoint, both themes, zero scroll, zero a11y violations.
- Home's win-probability card slots naturally into the existing card stack, reuses the same section-header/accent-square convention as every other card.
- Cross-page consistency strong: PositionBadge, the "You" badge, stale banner, ReasonChips/WhySheet, `tabular-nums` figures all pixel-identical across Home/Matchup/League/Waivers/Lineup -- the Waivers/Lineup spot-check found zero regression from shared-component changes.
- Dark mode is first-class throughout every new section.
