## Summary

Phase 6 hardened Sideline for self-hosted release: an optional `APP_PASSWORD` login gate (HOST-8, signed HTTP-only session cookie, 30-day expiry, constant-time comparison, 5/min/IP rate limit), security headers and structured logging on every response, a Docker/Unraid self-hosting story (PUID/PGID defaults fixed to match the real entrypoint, a new Unraid Community Applications template, a full `docs/self-hosting.md` rewrite), a PWA manifest and icon set, and consolidated preseason/offseason states and League-page polish (desktop tables, "You" markers) across the UI. It ran in four batches (ADR-017): A and B built the features (one Major fixed: an unbounded-memory rate-limiter map; two Blockers fixed: a real axe color-contrast violation, a stale-test-caused red a11y suite); C ran the three gate-prep tasks (T6.4 full regression/fresh-install/upgrade/auth-e2e/60-minute soak, T6.5 whole-repo security review, T6.6 final UX review of every screen), all of which came back clean; D (the planned T6.7 fix round) was skipped because Batch C returned zero Blocker/Major findings to fix (logged as an ADR-017 amendment in `docs/DECISIONS.md`).

A real security bug was found and fixed during Batch A: `clientIp` trusted the spoofable FIRST `X-Forwarded-For` entry instead of the last (proxy-appended) one. T6.5's whole-repo security review independently re-traced the fix and confirmed it holds, along with the full auth lifecycle, the constant-time comparisons, and the rate limiter's bounded memory. `pnpm audit` has 7 advisories (4 high, 2 moderate, 1 low), every one traced to `@lhci/cli` or `drizzle-kit` (devDependencies only) and empirically confirmed absent from both the worker's `pnpm deploy --prod` output and the web's `.next/standalone` bundle -- zero runtime exposure.
