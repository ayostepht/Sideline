## Summary

Phase 4 shipped player trends and usage metrics, the waiver engine (candidate pool, Lineup
Impact, Waiver Score, two sorted views, rolling-priority advisor), the Waivers and Players pages,
Home's waiver-targets and risers cards, and a production Docker beta image (T4.1-T4.8c, T4.7),
landed in 7 batches, each reviewed (code-reviewer and, where UI changed, ux-reviewer) and fixed
before the next batch started. After implementation, Steph tried the app live (`pnpm dev:lan`
against her real synced league) and found 5 real issues, all fixed same-session.

This gate's own prep and live-data runs found and fixed three more real issues before declaring
PASS:

- **T4.9** (`624771b`): WAIVER-6d's `computeNextWaiverClear` approximated America/New_York with a
  fixed UTC-5 offset, wrong by exactly one hour during EDT — roughly mid-March to early November,
  i.e. most of the NFL season. Found live by the orchestrator checking against Steph's real
  league settings (`waiver_day_of_week=2`, `waiver_clear_days=2`): on 2026-10-03 (EDT), the
  function computed a clear time that displayed as 4:00 AM ET against its own "3:00 ET" label.
  Fixed with the same `Intl`-based DST-aware technique `packages/providers/src/schedule.ts`
  already uses for kickoff times, reimplemented locally so `packages/core` stays dependency-free
  of `packages/providers`. Includes a 2-line orchestrator fix to a golden test that hardcoded the
  same wrong offset for a January/EST case.
- **T4.10** (`f6a8093`): no script existed anywhere to run the gate's own required check "beta
  image runs against live data for 30 minutes with healthy sync runs." Built `pnpm gate:soak
  [--minutes=N]`, reusable unchanged for Phase 6's 60-minute soak. Real credentials reach the
  container only via a temp 0600 `--env-file`, never the command line or a log file; the soak
  syncs into a fresh, anonymous Docker volume, never Steph's real `./data`.
- **G4 gate-run fix** (`974f380`): `pnpm gate`'s coverage-instrumented unit-test run (U2a) failed
  deterministically — not flakily — because V8 coverage instrumentation inflated WAIVER-2's
  450-Hungarian-solve perf test from ~266ms (real, isolated) to 2000-3800ms, blowing both its own
  margin and the real 2000ms spec budget. Confirmed as a test-tooling artifact, not a production
  regression (7.5x real margin). Fixed by excluding `*.perf.test.ts` from `--coverage` runs only;
  `pnpm verify`/`test:unit` still run them with their real, meaningful budget assertions. The same
  qa-engineer run also found and fixed a second, unrelated issue in its own path: `e2e/pages.spec.ts`'s
  STATE-2/STATE-3 still asserted Waivers and Players render as stub placeholders, stale since
  T4.6a/T4.6b shipped real pages this phase.

The real 30-minute Docker soak test (run separately from `pnpm gate`, after the orchestrator paused
the host's own `pnpm dev:worker` to avoid two concurrent real Sleeper callers per ADR-002) passed
cleanly: 30m00s uptime, 15/15 sync runs succeeded, zero failures, zero stuck rows, container
removed afterward with none left behind.

The full-phase-diff code review and final UX review both passed clean (zero Blocker/Major each).
